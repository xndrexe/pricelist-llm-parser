# Архитектура

```
┌──────────────┐
│   входной    │   .xlsx / .csv / .html / .json
│     файл     │
└──────┬───────┘
       │
       ▼
┌──────────────────────┐
│  extractors/         │  диспетчер по расширению →
│  xlsx/csv/html/json  │  list[dict] (сырые строки, заголовки as-is)
└──────┬───────────────┘
       │ headers
       ▼
┌──────────────────────┐       fallback при неполном mapping
│  mapping/heuristic   │ ◀───────────────────────────────────┐
│  словарь синонимов   │                                     │
└──────┬───────────────┘                                     │
       │ ColumnMapping                                       │
       │                                                     │
       │            опционально --llm                        │
       │            ┌────────────────────────────────┐       │
       └──────────▶ │  mapping/llm                   │ ──────┘
                    │  httpx → Ollama /api/chat      │
                    │  format=json, qwen2.5:7b       │
                    └────────────────────────────────┘
       │
       ▼
┌──────────────────────┐
│   normalize.py       │  parse_price («12 345,67»),
│                      │  detect_currency, parse_in_stock,
│                      │  clean_article → PriceListItem
└──────┬───────────────┘
       │ items + warnings
       ▼
┌──────────────────────┐
│  formatters.py       │  emit_json (полный ParseResult)
│  JSON / CSV          │  emit_csv (только items)
└──────────────────────┘
```

## Слои

- **extractors/** — четыре независимых модуля, у каждого один публичный
  вызов `extract_<format>(path) -> list[dict]`. Никакой бизнес-логики,
  только структурное чтение. Добавление нового формата = новый файл +
  одна строка в диспетчере.
- **mapping/** — отдельный слой, потому что задача «угадать что за
  колонка» сильно нетривиальна и стоит её изолировать. `heuristic.py` —
  работа со словарём синонимов, `llm.py` — отправка заголовков в локальную
  Ollama и парсинг ответа.
- **normalize.py** — превращение «сырого» dict в `PriceListItem`. Всё
  «прости меня, это же реальный мир» живёт здесь: «12 345,67», «по запросу»
  в цене, «да/нет/+/-» в наличии, доллар внутри строки цены.
- **schema.py** — `PriceListItem`, `ColumnMapping`, `ParseResult`. Pydantic
  ловит ошибки на границе и не пускает мусор дальше.
- **cli.py** — собирает пайплайн и разбирает аргументы. Бизнес-логики
  внутри минимум — почти все шаги это `extract → map → normalize → emit`.

## Почему именно так

- **Чёткий контракт между слоями.** Извлекатель не знает про схему,
  mapping не знает про сериализацию. Это делает каждый слой пригодным
  для отдельного теста (что и видно в `tests/`).
- **Эвристика по умолчанию, LLM по запросу.** Тащить локальную модель
  на каждый прогон — дорого и медленно. Большинство прайсов лезут под
  словарь синонимов. LLM включается только когда эвристика промахнулась.
- **Warning, а не fatal.** Реальные прайсы кривые: пустые цены, мусор
  в ячейках, «уточняйте по телефону». Пайплайн не падает — он сохраняет
  всё, что смог, и собирает предупреждения в `ParseResult.warnings`.
- **Никакой сетевой зависимости в эвристическом режиме.** Без `--llm`
  утилита работает оффлайн, что критично для конфиденциальных прайсов.

## Что осознанно НЕ сделано

- **Без авто-детекции листа в xlsx.** Если в книге несколько листов,
  берём только активный (первый). Прайсы с несколькими листами —
  отдельная задача, требующая UI/CLI-выбора.
- **Без поддержки .xls (старый Excel 97-2003).** openpyxl читает только
  xlsx. xlrd для старого формата ставит lxml-зависимости и устаревший
  Python — не оправдано для демо.
- **Без конвертации валют.** `price_rub` — это поле для удобства схемы,
  но мы НЕ дергаем ЦБ для конвертации USD → RUB. Цена сохраняется как
  есть, валюта помечается отдельно — клиент конвертирует сам по своему
  курсу.
- **Без батч-режима по папке.** CLI принимает один файл. Для пачки —
  оборачивать в shell-цикл. Это сознательное упрощение, чтобы не плодить
  ошибки «один файл сломался, что делать с остальными» внутри утилиты.
- **Без retry на запросы к Ollama.** Локальный сервер либо есть и
  отвечает, либо нет. Сетевые ошибки → fallback на эвристику.
